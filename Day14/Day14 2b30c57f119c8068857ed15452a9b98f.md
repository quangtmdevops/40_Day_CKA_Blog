## Task 14/40

In this exercise, you will explore Taints and Tolerations in Kubernetes

### Task details November 22, 2025

- Taint both of your worker nodes as below
    
    worker01--> gpu=true:NoSchedule , worker02--> gpu=false:NoSchedule
    
    - gán taint:
        - `k taint node k8s-cka-cluster2-worker gpu=true:NoSchedule`
        - `k taint node k8s-cka-cluster2-worker2 gpu=false:NoSchedule`
- Create a new pod with the image nginx and see why it's not getting scheduled on worker nodes and control plane nodes.
    - tạo `pod.yaml` mà không gây tác động thật lên hệ thống: `k run pod4 --image nginx --dry-run=client -o yaml > pod.yaml`
    - `k get pod -o wide` để check, thấy Pod được vào Node 3
- Create a toleration on the pod gpu=true:NoSchedule to match with the taint on worker01
    
    ```jsx
    apiVersion: v1
    kind: Pod
    metadata:
      labels:
        env: test
      name: pod4
    spec:
      containers:
      - image: nginx
        name: pod4
        resources: {}
      tolerations:
      - key: "gpu"
        operator: "Equal"
        value: "true"
        effect: "NoSchedule"
      dnsPolicy: ClusterFirst
      restartPolicy: Always
    status: {}
    
    ```
    
- The pod should be scheduled now on worker01
    - It was scheduled on worker01
- Delete the taint on the control plane node
    - untainted: `k taint node k8s-cka-cluster2-worker gpu=true:NoSchedule-`
- Create a new pod with the image redis , it should be scheduled on control plane node
    - `k run pod5 --image redis`
- Add the taint back on the control plane node(the one that was removed)
    - `k taint node k8s-cka-cluster2-worker gpu=true:NoSchedule`
    - Pod đang ở sẵn Node được add taint không bị Evicted mà vẫn sống.

## Note

**Note chung:**

- Taints được dùng để tạo ra 1 lớp cho Node
    - nhằm tạo ra 1 điều kiện nhất định để cho Pod chạy trên Node đó
    - các effect của Taints:
        - NoSchedule: Pod có Tolerations khớp với Taints thì mới được schedule trên Node đó.
        - PreferNoSchedule: Scheduler ưu tiên việc không đặt Pod lên Node này. Trường hợp bị hết Node thì vẫn có thể cho phép Schedule Pod.
        - NoExecute: lập tức xóa Pod khỏi Node nếu Toleration không khớp.
    - Ví dụ: Ta có 1 Node có GPU chỉ để chạy ứng dụng liên quan đến AI. Ta sẽ muốn những Pod chạy ứng dụng AI được triển khai trên Node này.
- Tolerations: được gán vào thêm cho Pod để có thể được Node chấp nhận
- flag `--dry-run=client` để in ra kết quả thử mà không gây tác động đến hệ thống thật.
- Khác biệt khi sử dụng Taint và NodeSelector:
    - 
        
        
        | Tiêu chí | Taints | NodeSelector |
        | --- | --- | --- |
        | cách chọn Pod | Pod có Toleration phù hợp | dựa trên label của Pod |
        | bối cảnh | Phục vụ cho những Node cần setup cho bài toán cụ thể   | sử dụng đơn giản, không cần xét nhiều điều kiện |
1. **Taints:**
    - gán Taints cho 1 Node: `k taint node k8s-cka-cluster2-worker gpu=true:NoSchedule`
2. **Toleration:**
    - không thể thêm trực tiếp vào Pod bằng command
    - cần add thêm vào manifest file của Pod đó
        
        ```jsx
        apiVersion: v1
        kind: Pod
        metadata:
          labels:
            run: redis
          name: redis
        spec:
          containers:
          - image: redis
            name: redis
          tolerations:
          - key: "gpu"
            operator: "Equal"
            value: "true"
            effect: "NoSchedule"
        ```
